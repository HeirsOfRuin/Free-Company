# Release: PWA, GitHub Pages, itch.io, Android

Five of the eight games shipped to itch.io and all eight target an installable
phone build. This is the checklist distilled from SR, CO, KA, LI and CF.

---

## Two shelves, one build

- **GitHub Pages** = where the game is *kept*: top-level https page, manifest and
  service worker at the same origin → installable, offline, keeps saves.
- **itch.io** = where the game is *found*: runs in a cross-origin frame on itch's
  domain → never installable (browsers only install top-level pages). Put the
  Pages link in itch's Links field: "Install it to your phone: <url> — same game,
  works with the network off."
- Saves do not cross between them (different origins). Offer save export as text.

## Pages

- Deploy from the **default branch** (the `github-pages` environment refuses
  others; SR lost eight deploys to this). Either branch deploy with `.nojekyll`
  (load-bearing: branch deploys run Jekyll and drop `_`-prefixed paths) or the
  Actions source. Do not run both (CO's redundant workflow failed every push).
- `actions/configure-pages` with enablement can switch Pages on for a repo that has
  never had it (CO, CF).
- The workflow should run tests and refuse to upload a build missing its manifest,
  worker or icons (CF): a 404 manifest makes the browser decline install silently.
- Manifest: explicit unique `id` inside scope (KA; SR's resolved outside scope),
  `start_url`, `display: standalone`, 192/512 and maskable icons generated by a
  committed tool.
- Service worker: `scripts/sw.js`; bump the cache name every release.
- Install UX: catch `beforeinstallprompt` and show an Install button; iOS Safari
  never fires it, so show "Share → Add to Home Screen" there (SR).

## itch.io

Settings that worked (CO `docs/itch-release.md` is the full worked example):
- Kind: HTML. Upload a zip with **index.html at the zip root**
  (`scripts/make-itch-zip.sh` checks). Tick "played in the browser".
- **Embed size: measure, don't guess.** CO measured five sizes: the frame capped at
  600px, sticky chrome 237px at 390 wide and 214px at 480 → 480x820 wasted nothing.
- Mobile friendly on, portrait; fullscreen button on.
- Cover 630x500 (required to appear in browse); check it at 315x250. Three
  screenshots that show the loop, the tactics and a consequence, no two alike.
- Strip service-worker registration for the itch build unless measured otherwise
  (SR: stale builds on itch's shared origin). Strip debug UI (`VITE_RELEASE=1`, KA).
- A loose HTML download alongside the zip plays offline from disk (SR) — except
  Safari, which refuses localStorage on file://; say so on the page.
- KA free demo: a separate build containing only the prologue and Chapter One (the
  later chapters are absent from the files, not hidden), ending on a page with the
  save code that the full game accepts.
- Make the whole kit one command (KA `npm run kit:itch`; LI `tools/itch.mjs`).

**Before going public:**
- [ ] Play the uploaded zip, served over http inside a sandboxed cross-origin
      iframe, with storage blocked: it must start and say nothing will be kept.
- [ ] No uncaught errors in the frame (TL/CO: `navigator.serviceWorker` getter
      throws in a sandbox).
- [ ] Every count in the page copy read out of the build (CO: 5 employers, 8
      doctrines, 60 seasons...). "No claim here is aspirational."
- [ ] Tutorial and help re-read against the build (F6).
- [ ] Privacy line exact: no account, no ads, no analytics, and name anything that
      does leave the page (CO: Google Fonts). Better: self-host fonts (VK bundles
      `@fontsource`), so the offline build keeps its typography.
- [ ] Store screenshots generated from the real game driven through its own
      functions (CO `make-press.js`; SR seeded a sensible mid-game state and cleared
      first-visit hints first — "33 of 10 loads" reads as a bug on a store page).
- [ ] State known constraints on the page (saves in browser storage; win rate by
      difficulty; which difficulty to start on).

## Hosts that wrap the document

Some hosts (Claude artifacts) wrap your HTML in their own doctype/head/body. Keep a
body-only entry next to `index.html` (TL `artifact-index.html`, CF
`centennial-farm.embed.html`): head elements that must survive moved into the body,
a background stated up front, `color-scheme` declared, safe-area tokens zeroed
because the host already padded the notch. Deliberately a near-duplicate kept in
the repo so a change to one is visible beside the other.

## Android (KA)

Capacitor wraps the release build in a WebView; a GitHub workflow builds the APK
on push and attaches it to the run. Signing key from secrets
(`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`), never in the repo;
without them it builds a test APK. Version code = run number so each build
installs over the last. See KA `docs/ANDROID.md`, SR `docs/android.md`.
